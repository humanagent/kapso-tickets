How it works

One tool. Plugs into the image skill you already have.

Kapso agent nodes can already send images through UI skills, but the image has to exist at a URL first. This fills that gap: the agent generates the image from the conversation.

01

The agent collects the order

Store, items, quantities, prices, payment method. Whatever the conversation already has.

02

It calls render_ticket

POST /tickets validates the order, computes subtotal, discount, IVA and total, and returns an image_url.

03

The image skill sends it

The URL goes straight into the image UI skill. The customer gets a receipt, not a wall of text.

API

JSON in. Image URL out.

No storage: the ticket lives in the URL, so every image is cacheable forever and stays under WhatsApp's 2,048-character image_url limit. Bad input comes back as a 400 the agent can read and fix.

requestPOST /tickets
curl -X POST $HOST/tickets \
  -H 'content-type: application/json' \
  -d '{
  "store": { "name": "Café Tortoni" },
  "items": [
    { "name": "Café con leche", "qty": 2, "price": 4200 },
    { "name": "Medialunas",     "qty": 3, "price": 1500 }
  ],
  "taxRate": 0.21,
  "payment": "Mercado Pago"
}'
response200
{
  "image_url": "https://…/t/eyJzdG9y….png",

  }
}

// then, in the agent node:
send_ui_ticket({ image_url, caption: "Tu ticket 👇" })

Why

The model sends data. The template draws it.

Totals in code

The model passes items and prices. Subtotal, discount, tax and total are computed in integer cents on the server, so the number on the receipt is the number you charge.

Readable at a glance

Five lines of items as text get lost in a chat. A receipt is a format people already trust and screenshot.

Same pattern, more formats

Tickets first. The same renderer can do order status, booking confirmations and small charts for backoffice assistants.
